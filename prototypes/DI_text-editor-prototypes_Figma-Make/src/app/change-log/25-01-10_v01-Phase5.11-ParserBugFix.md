# Phase 5.11: Parser Bug Fix - OR IF Context Issue

**Date:** January 10, 2025  
**Type:** Bug Fix  
**Status:** Complete

## Summary

Fixed critical parser bugs that prevented complex nested IF statements with "or if" clauses and natural language operators from parsing correctly. The root cause was context-insensitive handling of multi-token patterns.

## Problem

The formula parser was failing on this valid formula:
```
if $orderTotal is greater than 1000 and
  if $loyaltyTier is "gold" then multiply $orderTotal by 0.15
  or if $loyaltyTier is "silver" then multiply $orderTotal by 0.10
  otherwise multiply $orderTotal by 0.05
otherwise 0
```

Two bugs were present:
1. **Missing ParseContext enum** - Referenced but never defined, causing ReferenceError
2. **Missing tokenize import** - Used but never imported, causing ReferenceError  
3. **Context-insensitive OR IF** - "OR IF" was treated as a block terminator globally, causing false positives when OR appeared in other contexts (like before natural language operators)

## Root Cause

### Bug 1: Missing Enum Definition
`ParseContext` was referenced in the parser class but never defined:
```typescript
private context: ParseContext = ParseContext.Statement; // ❌ ParseContext not defined
```

### Bug 2: Missing Import
The `tokenize` function from `Tokenizer.ts` was never imported but was used in the `parse()` method.

### Bug 3: Context-Insensitive Pattern Matching
`isBlockTerminator()` was checking for "OR IF" pattern globally:
```typescript
// ❌ WRONG - Creates false positives
if (this.check('OR') && this.peekNext()?.type === 'IF') {
  return true; // Treats ANY "or if" as block terminator
}
```

When parsing:
```
multiply $orderTotal by 0.15
or if $loyaltyTier is "silver" then ...
```

After parsing "multiply $orderTotal by 0.15", the parser would see "OR IF" and incorrectly think the statement block had ended, even though "or if" belonged to the parent IF as an ELSEIF clause.

## Solution

### Fix 1: Define ParseContext Enum
Added the missing enum definition:
```typescript
/**
 * Parse Context
 * 
 * Track what parsing context we're in to handle ambiguous tokens.
 * For example, "IS" can be comparison operator or part of predicate function.
 */
enum ParseContext {
  Statement = 'Statement',
  Expression = 'Expression',
  Comparison = 'Comparison'
}
```

### Fix 2: Add Missing Imports
Added imports at the top of FormulaParser.ts:
```typescript
import { tokenize } from './Tokenizer';
import type { Token, TokenType } from './Tokenizer';
import type { /* ... AST types ... */ } from '../ast';
import { resolveVerbalization, type VerbalizationMap } from '../verbalization';
```

### Fix 3: Context-Aware Pattern Recognition
Removed "OR IF" check from `isBlockTerminator()`:
```typescript
/**
 * Check if current token is a block terminator
 * 
 * NOTE: We do NOT check for "OR IF" here because OR can appear in many contexts
 * (logical OR, "or if" as ELSEIF, etc.). We only recognize "or if" as ELSEIF
 * in the matchElseIf() function where context makes it unambiguous.
 */
private isBlockTerminator(): boolean {
  // Check for simple single-token terminators
  if (
    this.check('END') ||
    this.check('ELSE') ||
    this.check('OTHERWISE') ||
    this.check('ELSEIF') ||
    // ... other terminators
  ) {
    return true;
  }
  
  // Check for ELSE IF (two tokens)
  if (this.check('ELSE') && this.peekNext()?.type === 'IF') {
    return true;
  }
  
  // ✅ REMOVED: OR IF check (handled in matchElseIf() instead)
  
  return false;
}
```

"OR IF" is now **only** recognized in `matchElseIf()` where the context makes it unambiguous:
```typescript
private matchElseIf(): boolean {
  // Check for ELSEIF (single token)
  if (this.check('ELSEIF')) {
    this.advance();
    return true;
  }
  
  // Check for ELSE IF (two tokens)
  if (this.check('ELSE') && this.peekNext()?.type === 'IF') {
    this.advance();
    this.advance();
    return true;
  }
  
  // ✅ Check for OR IF (only in ELSEIF matching context)
  if (this.check('OR') && this.peekNext()?.type === 'IF') {
    this.advance();
    this.advance();
    return true;
  }
  
  return false;
}
```

## Key Principle

**Context-Aware Parsing:** Multi-token patterns should only be recognized in the specific parsing contexts where they're expected, not globally.

This is especially important when tokens can appear in multiple contexts with different meanings:
- OR as logical operator: `$x > 5 OR $y < 10`
- OR IF as ELSEIF variant: `if X then Y or if Z then W`

## Lessons Learned

1. **Always define referenced types** - Don't reference enums/types without defining them first
2. **Always import used functions** - The tokenize function must be imported before use
3. **Multi-token patterns need context** - Same token sequence can mean different things in different contexts
4. **Minimal, surgical fixes** - Don't add complex mode systems when a simple context check solves the problem
5. **Document the why** - Explain why certain checks are NOT present (e.g., why OR IF isn't in isBlockTerminator)
