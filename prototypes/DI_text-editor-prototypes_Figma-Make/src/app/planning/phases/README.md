# Planning - Phases

This directory contains phase documentation and completion summaries for multi-phase implementations.

## Purpose

Phase documents describe:
- **Phase structure** - How a large feature was broken into phases
- **Visual demonstrations** - Screenshots, diagrams, and usage examples
- **Complete summaries** - Final implementation summaries for multi-increment features
- **Success criteria** - What each phase accomplished

## Directory Contents

### Phase Documentation

- **PHASE3_VISUAL_DEMO.md** - Formula Debugger Phase 3 visual demonstration and user guide
- **LIST_ARRAY_COMPLETE_SUMMARY.md** - Complete summary of List/Array type implementation (Increments 1-3)

## Relationship to Other Documentation

| Directory | Purpose | Content Type |
|-----------|---------|--------------|
| `/planning/phases/` | Multi-phase summaries and demos | Phase completion documentation |
| `/planning/epics/` | Large initiatives spanning multiple phases | EPIC-level tracking |
| `/planning/requirements/` | Individual feature plans | Feature/phase requirements |
| `/change-log/` | Chronological implementation logs | What was implemented when |

## When to Create Phase Documents

Create phase documentation when:
- ✅ Completing a major phase of a multi-phase feature
- ✅ Documenting visual/UX demonstrations for stakeholders
- ✅ Summarizing a complete multi-increment implementation
- ✅ Creating user-facing guides for complex features

Do NOT create phase documents for:
- ❌ Individual implementation logs (use `/change-log/`)
- ❌ Future phase plans (use `/planning/requirements/`)
- ❌ EPIC-level tracking (use `/planning/epics/`)

## Format Guidelines

Phase documents should include:
- Clear status and completion date
- Visual examples (ASCII art, diagrams, examples)
- Complete feature overview
- User experience documentation
- Links to related implementation logs and requirements
- Next steps or future enhancements
